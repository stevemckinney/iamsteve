# Astro migration

Move iamsteve.me from Next.js 16 (App Router) to Astro 7, with the same URLs, markup, headers and behaviour. Today about half of each page’s HTML is the inlined React Server Components payload (roughly 250 KB uncompressed on `/`, a post and `/collections`), and every page loads 14–17 JS files. Astro drops that payload and ships JavaScript only for the parts that need it. It also means fewer Next.js security bumps (#329, #367), matches Steve’s other Astro sites (mcknny, parchment, ams, helen) and leaves a path to Cloudflare later. This file is the working plan and the checklist the port is measured against.

**Working on the branch:**

- `pnpm exec astro dev` and `pnpm exec astro build` run Astro. `pnpm dev` and `pnpm build` still run Next.js until cutover.
- The Vercel adapter writes the build to `.vercel/output`: prerendered files in `static/`, and every route with `prerender = false` in one Node function, `functions/_render.func`. The adapter has no `astro preview`, so `node scripts/serve.mjs [--port 4321]` serves the output the way Vercel routes it (`vercel.json` merged with the adapter’s routes, static files, then the functions), with the functions reading `.env` and `.env.local`. It follows Vercel closely enough to catch mistakes in `vercel.json`, but only a preview settles how Vercel treats it.
- `pnpm exec playwright test` runs the tests in `tests/` against `scripts/serve.mjs` on port 4310 (`PORT` changes it), so build first. The fixtures in `tests/fixtures.js` block requests to other hosts and fail a test on any uncaught page error. `.env.local` holds real keys, so tests mock EmailOctopus, Cloudflare, Turnstile and Supabase writes in the browser, or only call endpoints on paths that return before the upstream call. A form post to `/api/newsletter` runs the function in the test’s own process, against a local stand-in for EmailOctopus. On a new machine, `pnpm exec playwright install chromium` first.
- `node scripts/parity.mjs` checks the build in `.vercel/output/static` against production: URLs, heads, normalised bodies and other text files byte for byte (`--help` lists options; `--refresh` re-crawls). Production URLs that the build serves on demand (`/search?q=…`, for example) go through the function. Accepted differences, each with its reason, are in `scripts/parity-expected.json`.
  - Build in UTC (`TZ=UTC`), as Vercel does: dates are formatted in the build machine’s time zone.
  - For counts that match production, build with `NEXT_PUBLIC_ENABLE_VIEW_COUNTING=true` and `NEXT_PUBLIC_DB_VIEWS_TABLE=pages`. The view counter’s tests need the first too, or the page has no counter. Locally, `.env.local` names `pages_dev` and has no `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, so local builds of either framework show no popular posts or post views.
- `node scripts/edge-check.mjs <target> [--expected]` sends 138 requests to a target and to `https://iamsteve.vercel.app` (production without Cloudflare), and compares status, `Location`, the edge headers, and the markdown and 410 bodies. Accepted differences are in the script, each with its reason; `--expected` lists them. For a preview, `VERCEL_BYPASS` holds the protection bypass secret, sent to the target only. It sends GET and OPTIONS only, so nothing is written.
- `node scripts/compare-posts.mjs [slug …]` diffs post bodies in `.vercel/output/static` against the live site (cached in `node_modules/.cache/compare-posts`).
- Merge `origin/main` often. A change main makes in `app/` or `components/` is a change to port; content, `lib/` and `css/` changes apply to both builds as they are.
- Commit only after `astro build` passes.

## Decisions to revisit

- **Hosting move timing:** Cloudflare hosting and D1 for views, after cutover.
- **Tracking-parameter stripping:** `_strip`, a small function, keeps the other parameters as `proxy.js` does. Dropping the rule and relying on canonicals would save the function and a hop.
- **Freshness:** daily rebuild by default. Alternatives: ISR on chosen on-demand routes, or a GET count endpoint.
- **React islands long term:** replace react-aria islands with native HTML where the interaction is simple, as mcknny does.
- **RSS alternate:** on every page (recommended) or exact parity (4 routes).
- **Drafts exposure:** `/blog/drafts` and `/blog/drafts/*` are public today. Prerender as now, build them in dev only, or drop them.
- **Env var names:** `astro.config.mjs` declares today’s names, `NEXT_PUBLIC_*` included, as server values in `astro:env`, which accepts them; prerendered pages read theirs at build through `import.meta.env`. Rename at cutover, or keep them.
- **Formatting:** Prettier 3 with `prettier-plugin-astro`, or no formatter for `.astro` files.
- **ClientRouter:** only if MPA navigation doesn’t feel right after parity.
- **Quirks ported as is:** the known bugs marked “Ported as is” keep the parity diffs readable. Fix them in one pass once parity holds, or after cutover.
- **Bento grid CSS:** about 375 bytes inline on every post. Accept it, or load it with the bento post only.
